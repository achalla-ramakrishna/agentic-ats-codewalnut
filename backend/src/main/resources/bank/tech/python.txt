- The app has too many migrations; fix it by squashing them into one file

Q H Why are async endpoints in FastAPI harmed by calling a blocking function like time.sleep or requests.get?

- They make FastAPI return 404 for that route

Q E What does the GIL (Global Interpreter Lock) in CPython do?
+ Lets one thread at a time run Python bytecode in a process
- Locks each file while a thread is writing to it
- Stops threads from importing modules at the same time
- Encrypts the interpreter's memory between threads
= Threads still help with I/O-bound work, because the GIL is released while waiting.

Q E Which keyword pauses a coroutine until an awaitable finishes?

- yield from only
- wait
- pause
= await can only be used inside async def functions.

Q E Which is best for many slow network calls?
+ asyncio or threads
- One process per call
- A tight for loop
- time.sleep between calls
= I/O-bound work spends its time waiting, so concurrency helps.

Q E Which is best for CPU-heavy work such as image processing on many cores?
+ multiprocessing
- threading
- asyncio
- generators
= Separate processes each have their own interpreter and GIL, so they use several cores.

Q M What happens if you call an async function without await (e.g. hello())?

- It runs immediately like a normal function
- It raises SyntaxError
- It runs in a new thread
= Python warns "coroutine was never awaited".

Q M What does asyncio.gather(a(), b()) do?
+ Runs both concurrently and returns their results in order
- Runs a() to the end, then starts b() and waits for it
- Runs each coroutine in its own operating system process
- Returns only the result of whichever finishes first
= Total time is roughly the longest of the two, not the sum.

Q M What does ThreadPoolExecutor.map(fetch, urls) give you?
+ fetch's results for each URL, run on threads, in input order
- fetch's results for each URL, in the order they finish
- Only the result of the first URL that finishes
- The list of thread objects that were started
= Use as_completed if you want results as they finish.

Q H Two threads each run counter += 1 a million times. Is the final total guaranteed to be two million?
+ No; += takes several steps, and a switch between them can lose updates
- Yes, because the GIL makes every += operation atomic
- Yes, because ints are immutable and cannot be corrupted
- No, because Python raises an error when two threads write
= The GIL protects the interpreter, not your logic. Use a threading.Lock.

Q H In an async web app, a request handler calls a CPU-heavy function directly. What is the effect?
+ The event loop is blocked, so every other request waits
- Only that request slows down
- Python moves it to another core automatically
- The function is skipped
= Offload with loop.run_in_executor (a process pool for CPU work).

Q H Why can multiprocessing be slower than expected for small tasks?
+ Starting processes and pickling data can cost more than the work
- All processes share one GIL, so only one can run at a time
- Processes cannot return values to the parent process
- multiprocessing uses only one CPU core by default
= Batch work into larger chunks to amortise the overhead.

Q H What does Python 3.13 offer regarding the GIL?
+ An experimental free-threaded build without the GIL
- The GIL has been removed from every Python build
- The GIL now also locks across separate processes
- Threads were removed in favour of asyncio
= The default build still has the GIL; the free-threaded build (python3.13t) is opt-in.
