Q E What is the time complexity of reading the element at index i of an array?
+ O(1)
- O(n)
- O(log n)
- O(i²)
= Arrays store elements next to each other, so the address is computed directly.

Q E What is the time complexity of finding a value in an unsorted array of n elements?
+ O(n)
- O(1)
- O(log n)
- O(n log n)
= In the worst case every element is checked once.

Q E Which grows fastest as n becomes large?
+ O(2ⁿ)
- O(n²)
- O(n log n)
- O(n³)
= Exponential growth outpaces any polynomial.

Q E What does Big-O describe?
+ How cost grows as the input grows
- The exact running time in seconds
- The number of lines in a program
- The memory used by the compiler
= Constants and lower-order terms are dropped: 3n² + 5n is O(n²).

Q H What is the recurrence for merge sort, and what does it solve to?
+ T(n) = 2T(n/2) + O(n), which is O(n log n)
- T(n) = T(n−1) + O(n), which is O(n log n)
- T(n) = 2T(n/2) + O(1), which is O(n²)
- T(n) = T(n/2) + O(n), which is O(log n)
= Two half-size subproblems plus a linear merge.

= Random or median-of-three pivots make this unlikely.
