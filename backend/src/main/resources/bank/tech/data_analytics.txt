Q M Why is XLOOKUP often preferred over VLOOKUP?
+ It can look left and isn't broken by new columns
- It is the only lookup that works with text values
- It runs on Google Sheets but VLOOKUP does not
- It sorts the lookup range before it searches
= VLOOKUP uses a column number, which breaks when columns are inserted, and only looks right.

Q M A VLOOKUP returns the wrong row for an ID that isn't in the table. What is the likely cause?
+ The last argument is TRUE or missing, so it matches approximately
- VLOOKUP only works when the table has fewer than 100 rows
- The lookup column must be the last column of the table
- VLOOKUP cannot be used when IDs are stored as numbers
= Pass FALSE (or 0) for an exact match, or use XLOOKUP.

Q M What does =COUNTIFS(A:A,"North",C:C,">1000") count?

- Rows where A is North or C is over 1000
- The sum of C for rows where A is North
- The number of distinct values in A and C
= Every condition in COUNTIFS must be met.

Q H A sales sheet has dates in column A. How do you total sales for March 2026 only?

- SUM the column, then divide the total by twelve
- COUNTIF the dates and multiply by the average sale

Q H What does =A2&B2 return when A2 is 10 and B2 is 20?

- 200

Q H What does Power Query (Get & Transform) add to Excel?

- Drownings cause people to buy more ice cream

Q M A correlation coefficient is −0.9. What does it mean?

- A strong relationship where both rise together
- An error, since correlation can't be negative

- Revenue is always counted before discounts

Q H A distribution of incomes is right-skewed. How do mean and median usually compare?

- The median is higher than the mean
- The mean and median are always equal

Q H Each region's conversion rose this month, yet overall conversion fell. What explains it?

Q H Why report a confidence interval and not only a single average?

- It turns a sample into the full population

@topic da-sql-analysis | FUNDAMENTALS | SQL for analysis | SELECT and filters, GROUP BY with aggregates, HAVING, joins for reporting, dates, CASE for buckets and avoiding double counting.

Q E Which join keeps every customer, even those with no orders?

- customers INNER JOIN orders
- orders LEFT JOIN customers

Q M What does this return?

|        COUNT(*)

Q M Revenue doubled after joining orders to order_items. Why?
+ Each order repeats once per item, so its total is summed again
- LEFT JOIN always doubles the values in numeric columns
- SUM counts NULL values as equal to the largest amount
- The join changes the currency of the amount column
= Sum at the right grain: aggregate items first, or sum item-level amounts.

Q M How do you group orders by month in MySQL?

- GROUP BY MONTH(created_at) only
- GROUP BY created_at / 30
- ORDER BY created_at MONTHLY

Q M What does AVG(discount) do with rows where discount is NULL?

- It returns NULL overall
- It raises an error
= To treat missing as zero, use AVG(COALESCE(discount, 0)).

Q H Which query finds each customer's first order date?

Q H How do you get each month's revenue next to the previous month's?

- LEAD(revenue) GROUP BY month
- SUM(revenue) OVER (PARTITION BY month)
- PREVIOUS(revenue) ORDER BY month
= Run it over a monthly totals CTE; month-on-month change is revenue − LAG(revenue).

Q H A report counts users who did not buy using WHERE user_id NOT IN (SELECT user_id FROM orders). It returns 0. Why?

- NOT IN compares text, so numeric IDs never match at all

Q H What does this compute?

- The number of orders that were refunded

= Multiplying by 1.0 avoids integer division, which would round to 0.

- Faster support always lowers satisfaction
= Pair a target metric with a guardrail metric (Goodhart's law).

Q H Why define a metric precisely, e.g. "active = did X in the last 28 days"?
+ So everyone computes the same number
- So the dashboard loads more quickly
- So the metric always goes up over time
- So nobody can question the number again
= A metrics dictionary prevents teams from reporting different numbers for the same name.

@topic da-modelling | ADVANCED | Data modelling and warehousing | Facts and dimensions, star schemas, grain, slowly changing dimensions, ETL vs ELT, warehouses and dbt.
Q E In a star schema, what is a fact table?
+ A table of events or measures, e.g. sales
- A table that describes products or people
- A table that stores user passwords
- A table that holds only one row
= Dimension tables (product, customer, date) describe the facts.

Q E What is a data warehouse?
+ A store built for analysis, from many sources
- A server that runs the live checkout app
- A folder where backups of code are kept
- A spreadsheet shared with every team
= Snowflake, BigQuery, Redshift and Synapse are common warehouses.

Q E What does ETL stand for?
+ Extract, transform, load
- Export, test, launch
- Edit, track, list
- Encrypt, transfer, log
= In ELT, raw data is loaded first and transformed inside the warehouse.

Q E What is a dimension table?
+ Descriptive details, e.g. product name
- Numeric events, e.g. each payment
- A log of failed pipeline runs
- A list of database user accounts
= Facts hold keys to dimensions plus measures.

Q M What is the grain of a fact table?
+ What one row represents
- How many columns it has
- How often it is refreshed
- The size of the file on disk
= E.g. "one row per order line". Mixing grains causes double counting.

Q M Why use a separate date dimension table?
+ Easy grouping by week, quarter or holiday
- Dates can't be stored in fact tables
- It makes the warehouse use less space
- Warehouses refuse raw date columns
= It holds attributes such as fiscal quarter, weekday and public holiday.

Q M What does dbt do?
+ Runs tested, versioned SQL transforms in the warehouse
- Moves files between cloud buckets on a schedule
- Draws dashboards straight from database tables
- Replaces the warehouse with a local database
= Models are SELECT statements; dbt handles dependencies, tests and docs.

Q M Why are analytics tables often denormalised?
+ Fewer joins make reporting simpler and faster
- Normalised tables can't be queried with SQL
- It removes the need for any data quality
- Denormalised tables never need refreshing
= Warehouses trade storage for read speed and simpler queries.

Q H A customer moves from Pune to Delhi. How does a type 2 slowly changing dimension handle it?
+ Adds a new row with dates; keeps the old
- Overwrites the city, losing the old value
- Deletes the customer and re-creates them
- Stores both cities in a single text field
= Past sales stay linked to Pune; new sales link to Delhi.

Q H Why use a surrogate key in a dimension instead of the source system's ID?
+ It survives source changes and type 2 history
- Source IDs can never be used in any join
- Surrogate keys make the table encrypted
- It lets the warehouse skip all indexes
= Several rows for one customer (type 2) need distinct keys.

Q H What is the main benefit of ELT over ETL with a modern cloud warehouse?
+ Raw data is kept, and transforms can be rerun
- ELT never needs any SQL to be written
- ELT avoids storing any data in the cloud
- ELT runs without any compute costs at all
= Cheap storage and elastic compute make transforming in place practical.

Q H An incremental model loads only new rows by created_at. What can go wrong?
+ Late or updated rows are missed
- Old rows load twice every night
- The table can never be rebuilt
- Incremental models can't use SQL
= Use updated_at with a look-back window, or rebuild periodically.

@topic da-experiments | ADVANCED | A/B testing and inference | Hypotheses, control and treatment, p-values, significance and power, sample size, guardrails and common testing mistakes.
Q E What is an A/B test?
+ Comparing two random groups shown different versions
- Asking two users which design they like better
- Testing a page in two browsers to find bugs
- Launching to everyone, then comparing months
= Random assignment makes other differences average out.

Q E What is the control group?
+ Users who see the current version
- Users who see the new version
- Users who left the experiment
- Users who report problems
= The treatment group sees the change.

Q E Why must users be split at random?
+ So the groups are alike except for the change
- So each user can see both versions in turn
- So the test finishes in less than one day
- So the result is always significant
= Picking users by hand introduces bias.

Q E What is the null hypothesis in an A/B test?
+ The change makes no difference
- The change always improves results
- The control version has a bug
- The sample size is too large
= The test asks whether data is surprising if there's no real effect.

Q M What does a p-value of 0.03 mean?
+ Data this extreme has a 3% chance if there's no effect
- There is a 97% chance that the new version is better
- 3% of users preferred the new version to the old one
- The effect size is 3% higher in the treatment group
= It is not the probability that the hypothesis is true.

Q M Why decide the sample size before starting a test?
+ So you can detect the effect you care about
- So the test can be stopped at any time
- So more users see the winning version
- So the p-value is always below 0.05
= Power analysis uses the baseline rate, minimum effect and significance level.

Q M A test is checked daily and stopped the first day p < 0.05. What's wrong?
+ Peeking inflates false positives
- Daily checks slow down the website
- Tests must run for exactly one year
- p < 0.05 is never significant
= Fix the duration in advance, or use sequential testing methods.

Q M A test was significant but lifted conversion by 0.01%. What should you consider?
+ Whether the lift is worth the cost
- Whether the test should run forever
- Whether the result should be hidden
- Whether to change the p-value cut-off
= Statistical significance is not practical significance.

Q H Twenty metrics are tested at α = 0.05 with no real effects. About how many will look significant?
+ About 1
- About 5
- None
- All 20
= 20 × 0.05 = 1. Correct for multiple comparisons or pick one primary metric.

Q H The treatment raised clicks but lowered purchases. What role do guardrail metrics play?
+ They catch harm the main metric misses
- They make the test finish more quickly
- They choose which users join the test
- They replace the need for a control group
= Define guardrails (revenue, errors, latency) before the test starts.

Q H The split was meant to be 50/50 but came out 52/48 on 100,000 users. What should you do?
+ Investigate a sample ratio mismatch first
- Ignore it; small gaps never matter here
- Delete users until both groups are equal
- Report the result, since it's close enough
= A 4,000-user gap is far beyond chance at this size; a bug in assignment or logging can bias results.

Q H A new feature shows a big lift in week one that fades by week four. What is a likely reason?
+ A novelty effect wore off
- The control group got smaller
- The p-value was set too low
- Users were split by region
= Run tests long enough, and look at the effect over time.

@topic da-advanced-analysis | ADVANCED | Advanced analysis and forecasting | Cohort and funnel analysis, segmentation, time series and seasonality, forecasting, regression basics and attribution.
Q E What is customer segmentation?
+ Grouping customers by shared traits or behaviour
- Splitting a database table into smaller files
- Sending every customer the same message
- Removing customers who have stopped buying
= Segments such as RFM (recency, frequency, monetary) guide targeting.

Q E What is seasonality in a time series?
+ A pattern that repeats on a calendar cycle
- A sudden one-off spike from a single event
- A slow, steady rise over several years
- Random noise with no pattern at all
= E.g. retail peaks every Diwali or December.

Q E What does a moving average do to a noisy daily series?
+ Smooths it to show the trend
- Removes all the seasonality
- Predicts next year's values
- Doubles the size of the data
= A 7-day moving average removes the weekday pattern.

Q E What does linear regression estimate?
+ How an outcome changes as inputs change
- Which category each row belongs to
- How many clusters the data contains
- The median of the outcome only
= The coefficient is the change in outcome per unit change of the input.

Q M Why compare this December with last December, not with November?
+ It removes the seasonal effect
- November data is never reliable
- Months can only be compared yearly
- December always has more data rows
= Year-over-year comparisons cancel out the yearly cycle.

Q M What is last-click attribution?
+ Credit goes to the final touch before the sale
- Credit is shared equally among all touches
- Credit goes to the first ad a user saw
- Credit goes to the most expensive channel
= It undervalues channels that start the journey, such as display or social.

Q M A regression has R² = 0.85. What does it mean?
+ The model explains 85% of the outcome's variance
- The model is correct for 85% of the rows
- 85% of the inputs are statistically significant
- There is an 85% chance that the model is right
= A high R² doesn't show causation or guarantee good forecasts.

Q M Which RFM segment usually deserves a win-back campaign?
+ Big past spenders who haven't bought lately
- New customers who bought for the first time
- Frequent recent buyers who spend the most
- Visitors who have never bought anything
= High monetary and frequency but low recency signals at-risk value.

Q H Why should a forecast be shown as a range, not a single line?
+ The future is uncertain; a range shows it
- Single lines cannot be drawn by BI tools
- Ranges make the forecast always correct
- A single line hides the historical data
= Prediction intervals help plan for the high and low cases.

Q H A model predicting churn uses "cancellation date" as an input. What is the problem?
+ Data leakage: it's unknown at predict time
- Dates can't be used as model inputs at all
- The model will run too slowly in production
- Churn models must only use numeric inputs
= Leakage gives great test scores and useless real predictions.

Q H Sales rose after a TV campaign, but a competitor closed the same month. How do you estimate the campaign's effect?
+ Compare with a similar region without the campaign
- Credit the whole increase to the TV campaign
- Credit the whole increase to the competitor
- Average the sales before and after the month
= A control region (difference-in-differences) separates the two causes.

Q H Your churn model is 95% accurate, but only 5% of users churn. Why is accuracy misleading?
+ Predicting "no churn" for all also scores 95%
- Accuracy above 90% always means overfitting
- Accuracy can't be computed for churn models
- The model must be tested on training data
= Use precision, recall or AUC for imbalanced outcomes.
