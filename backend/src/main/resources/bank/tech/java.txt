Q H What does the parent-delegation model of class loading protect?
+ App classes can't replace core ones like String
- Application classes load faster than core ones
- Every class is loaded twice as a safety check
- Jar classes always load before the JDK's own
= A class loader asks its parent first.

Q H What does this print?
| static int depth = 0;
| static void down() { depth++; down(); }
| try { down(); } catch (StackOverflowError e) { System.out.println(depth > 1000); }
+ true
- false
- It never stops
- Compile error
= StackOverflowError is an Error that can be caught, though rarely should be.

Q H Why are strings deduplicated by G1's -XX:+UseStringDeduplication?
+ Equal strings share one char array to save heap
- Duplicate strings are deleted from the program
- All strings are interned into the string pool
- Strings are compressed with gzip in memory
= It targets the backing arrays, not the String objects.

Q H What does -XX:MaxRAMPercentage=75 do in a container?
+ Sizes the max heap to 75% of the container's memory limit
- Lets the JVM use 75% of the host machine's total RAM
- Reserves 75% of memory for thread stacks only
- Triggers GC whenever the heap is 75% full
= Container-aware sizing avoids hard-coding -Xmx per environment.

Q H What causes "GC overhead limit exceeded"?
+ Nearly all time goes to GC for little gain
- The GC thread crashed and must be restarted
- Too many GC threads were set with JVM flags
- The heap is too large to be scanned in one go
= It's a form of OutOfMemoryError; usually a leak or too small a heap.

@topic java-design | ADVANCED | Design principles and patterns | SOLID, singleton, factory, builder, strategy, observer and decorator patterns, immutability, refactoring code smells.
Q E What does the Single Responsibility Principle say?
+ A class should have one reason to change
- A class should be a singleton
- Every class should have one method
- Only one developer should edit a class
= Keeping one job per class makes changes smaller and safer.

Q E Which pattern makes sure a class has only one instance?
+ Singleton
- Factory
- Observer
- Adapter
= In Spring, beans are singletons by default, so you rarely hand-write this pattern.

Q E When is the Builder pattern useful?
+ Creating objects with many optional fields readably
- Making a class safe to share between threads
- Iterating over the elements of a collection
- Writing log messages in a consistent format
= e.g. User.builder().name("Asha").email("a@x.com").build() instead of a long constructor.

Q E What does DRY stand for?
+ Don't Repeat Yourself
- Do Run Yearly
- Data Requires Yielding
- Design, Review, Yield
= Keep each piece of knowledge in one place so a change is made once.

Q M What does the Open/Closed Principle mean?
+ Open for extension, closed for modification
- Classes should be open source and freely shared
- Fields should be public so others can extend them
- Files should be closed as soon as they are read
= Add new behaviour with new classes (e.g. a new strategy) rather than editing working code.

Q M What does the Strategy pattern do?
+ Swaps algorithms at run time behind a common interface
- Notifies many objects automatically when one object changes
- Wraps an object to add behaviour without changing its class
- Creates families of related objects without naming classes
= e.g. different PaymentStrategy implementations chosen per order.

Q M Why prefer immutable objects?
+ They are thread-safe and easier to reason about
- They always use less memory than mutable objects
- They are faster to create than mutable objects
- They are never removed by the garbage collector
= An object that cannot change can be shared freely between threads without locks.

Q M What does the Dependency Inversion Principle say?
+ High-level code should depend on abstractions, not concrete classes
- Lower layers should call upper layers instead of the other way round
- Every if condition should be inverted to reduce nesting in methods
- Dependencies should be listed in reverse order in the build file
= Depending on an interface (e.g. PaymentGateway) lets you swap implementations and test easily.

Q H Which is a classic violation of the Liskov Substitution Principle?
+ Square extends Rectangle, and setting the width also sets the height
- A class implements two interfaces that declare the same method
- An abstract class declares a constructor that subclasses must call
- A final class cannot be extended by any other class
= Code written for Rectangle breaks when given a Square, so Square is not a safe substitute.

Q H Which is a correct thread-safe, lazy singleton in Java?
+ The initialization-on-demand holder class, or an enum with one value
- A static field set in a getter without any synchronization
- Creating a new instance on every call
- Cloning the instance
= The JVM initialises the holder class only on first use, safely across threads.

Q H Where do you see the Observer pattern in practice?
+ Event listeners and publish–subscribe, e.g. Spring events
- Builders that create objects with many optional fields
- Database indexes that speed up lookups by key
- Logging levels that filter messages by importance
= Subjects publish events; observers react without the subject knowing them directly.

Q H What is the best fix for a "God class" that does everything?
+ Split it into smaller classes with one responsibility each
- Make all its methods static so it needs no instance
- Add detailed comments explaining every method in it
- Rename it so its name matches what it mostly does
= Extract cohesive groups of fields and methods into their own classes.

Q E What does the Factory pattern do?
+ Creates objects without exposing the exact class
- Ensures only one object exists in the app
- Adds behaviour to objects at run time
- Notifies objects when something changes
= E.g. a NotificationFactory returns EmailSender or SmsSender.

Q E What does KISS stand for in software design?
+ Keep it simple
- Keep interfaces small and static
- Know important system states
- Keep integration speed stable
= Prefer the simplest design that works.

Q E What does YAGNI mean?
+ Don't build features until they're needed
- Always add hooks for future features
- Write all code in one class first
- Test only the code you change
= "You aren't gonna need it."

Q E What is a code smell?
+ A sign the design may need improving
- A compile error caused by a typo
- A slow SQL query in the logs
- A security bug found in testing
= Long methods, duplicated code and huge classes are common smells.

Q E What does refactoring mean?
+ Improving code structure without changing behaviour
- Adding new features to existing code quickly
- Rewriting the whole system in another language
- Fixing bugs reported by users in production
= Tests make refactoring safe.

Q E Which pattern adds features to an object by wrapping it?
+ Decorator
- Singleton
- Factory
- Iterator
= Java I/O: new BufferedReader(new FileReader(f)).

Q E What is coupling?
+ How much one module depends on another
- How many lines of code a class has
- How many tests cover a module
- How fast two modules talk to each other
= Aim for low coupling and high cohesion.

Q E What is cohesion?
+ How focused a module's responsibilities are
- How many classes share one database
- How often a module is deployed
- How many people work on a module
= A class doing one job well is highly cohesive.

Q E Which pattern lets incompatible interfaces work together?
+ Adapter
- Observer
- Builder
- Prototype
= Arrays.asList adapts an array to the List interface.

Q E What does the Interface Segregation Principle say?
+ Prefer small, specific interfaces over one big one
- Every class must implement at least one interface
- Interfaces should never have default methods
- Keep all interfaces in a separate package
= Clients shouldn't depend on methods they don't use.

Q E What is the Iterator pattern?
+ Walking a collection without exposing it
- A loop that repeats a task until it fails
- A way to copy a collection into an array
- A thread that processes items one by one
= for-each works on anything Iterable.

Q E Why write small methods?
+ They're easier to read, test and reuse
- The JVM can only run short methods fast
- Long methods can't be compiled in Java
- Small methods use no memory at all
= A method name documents what a block does.

Q E What does the Template Method pattern do?
+ Fixes an algorithm's steps; subclasses fill some in
- Generates code from a template file at build time
- Copies objects from a prototype instance
- Lets objects subscribe to events from a subject
= The base class calls abstract hooks.

Q M Which pattern does this code use?

| class Checkout {
|     private final Discount d;

| }
+ Strategy
- Singleton
- Observer
- Adapter

Q M What is the main problem with a long chain of if/else on a type code?
+ Every new type changes the same code (breaks Open/Closed)
- Java limits if/else chains to ten branches only
- if/else is slower than any other construct
- The compiler warns on more than three branches
= Polymorphism or a map of strategies keeps changes local.

Q M Which pattern gives a simplified interface to a complex subsystem?
+ Facade
- Proxy
- Composite
- Flyweight
= E.g. an OrderService hiding payment, stock and shipping calls.

Q M What does the Proxy pattern do?
+ Stands in for an object to control access to it
- Copies an object to make a new instance
- Combines objects into a tree structure
- Shares objects to save memory
= Spring's @Transactional works through proxies.

Q M Why is a mutable singleton holding user data dangerous in a web app?
+ It's shared by all requests and threads
- Singletons can't hold data of any kind
- It forces the server to restart often
- Singletons are created once per request
= Keep singletons stateless or thread-safe.

Q M What does the Composite pattern model?
+ Trees where parts and wholes are treated alike
- Objects that change behaviour by state
- Copying an object field by field
- Queues of tasks for later execution
= E.g. a folder containing files and folders.

Q M What is the Command pattern useful for?
+ Wrapping requests as objects, e.g. for undo or queues
- Running shell commands from inside Java code
- Validating command-line arguments at startup
- Sending commands to the database in batches
= Each command knows how to execute (and maybe undo) itself.

Q M What is dependency injection's main design benefit?
+ Classes get collaborators from outside, so they're easy to swap and test
- Classes create every dependency themselves, so nothing is shared
- All dependencies become static, so access is faster
- The code compiles faster with fewer imports
= It applies the Dependency Inversion Principle.

Q M Which is a sign of "feature envy"?
+ A method uses another class's data more than its own
- A class has more features than its competitors
- Two methods have exactly the same name
- A method is called from too many places
= Move the method to the class whose data it uses.

Q M Why prefer composition when you'd otherwise subclass just to reuse code?
+ It avoids tight coupling to the parent's internals
- Subclassing is not allowed for reused code
- Composition makes classes compile faster
- Composition removes the need for interfaces
= "Favour composition over inheritance" (Effective Java).

Q M What does the State pattern do?
+ Changes an object's behaviour as its state changes
- Stores an object's state in a database table
- Shares one state object between all threads
- Records each state change for auditing
= E.g. an Order whose ship() behaves differently in PAID and CANCELLED.

Q M What is the "primitive obsession" smell?
+ Raw strings and ints instead of domain types
- Using too many objects where ints would do
- Using primitive arrays instead of lists
- Using long instead of int for every number
= An Email or Money type can validate itself.

Q M Which pattern lets you build a complex object step by step and is used by StringBuilder and Lombok @Builder?
+ Builder
- Factory
- Prototype
- Bridge
= Builders avoid telescoping constructors.

Q H Which code violates the Liskov Substitution Principle?

| }
+ Penguin: code expecting a Bird may break
- Bird, because fly has an empty body
- Neither; this design follows LSP fully
- Both, because they share a method name

Q H Why is an enum often the best way to write a singleton in Java?

- Enums are faster than every other kind of class
- Enums can be created many times with new
= Effective Java item 3.

Q H What is the main risk of the Service Locator pattern?
+ Hidden dependencies make testing harder
- It creates a new service for every call
- It only works with static methods in Java
- It forces all services to share one database
= Constructor injection makes dependencies explicit.

Q H A method takes 9 parameters, several booleans. What's the best refactor?
+ Introduce a parameter object or builder and split the flags
- Make all the parameters static fields of the class
- Rename the parameters with shorter names
- Add more overloads with different orders
= Boolean flags often hide two methods in one.

Q H What does "tell, don't ask" encourage?
+ Ask objects to act rather than pulling data out
- Always ask the user before changing any data
- Use getters for every field, never setters
- Log every method call before it runs at all
= It keeps behaviour with the data it needs.

Q H Why can deep inheritance trees become fragile?
+ Changes in a base class ripple unexpectedly to subclasses
- The JVM limits inheritance to three levels deep
- Each level doubles the memory each object uses
- Subclasses can't call any of their parents' methods
= The "fragile base class" problem.

Q H Which pattern does java.util.function.Function.andThen best illustrate?
+ Composing behaviours (a pipeline / decorator style)
- A singleton that holds one shared function
- A factory that builds new function classes
- An observer that listens for function calls
= Higher-order functions compose small behaviours.

Q H An Observer setup leaks memory. What's the usual cause?
+ Listeners are registered but never removed
- Observers use too many interfaces
- The subject is declared final
- Events are sent on the main thread
= The subject keeps strong references to every listener.

Q H What is the anemic domain model anti-pattern?
+ Entities hold data only; all logic lives in services
- Entities hold so much logic they can't be tested
- The database has no foreign keys at all
- Domain objects are created without constructors
= Rich domain objects keep rules next to their data.

Q H When is applying a design pattern a mistake?
+ When it adds complexity the problem doesn't need
- Whenever the code base is written in Java
- When the pattern comes from the Gang of Four
- When the team has used it once before
= Patterns are tools, not goals; start simple.

Q H Which SOLID principle does this code break?
| class Report {
|     String build() { ... }
|     void saveToDisk() { ... }
|     void email(String to) { ... }
| }
+ Single Responsibility
- Liskov Substitution
- Interface Segregation
- Dependency Inversion
= Building, storing and emailing change for different reasons.

Q H What's the value of immutable value objects such as Money in a domain model?
+ Safe to share and validated once
- Any thread can change them without locks
- They use less memory than primitive numbers
- They let the database skip its constraints
= Records make value objects concise in Java 16+.

@topic java-microservices | ADVANCED | Microservices and system design | Service boundaries, API gateways, REST vs messaging, resilience (circuit breakers, retries), idempotency, sagas, caching, JWT security, observability.
Q E What is a microservice?
+ An independently deployable service owning one business capability
- Any class in the codebase that has fewer than 100 lines of code
- A function inside a monolith that is called over HTTP internally
- A database table that is accessed by only one application
= Each service can be built, deployed and scaled on its own.

Q E Which format do most REST APIs use for request and response bodies?
+ JSON
- CSV
- Binary serialized Java objects
- Plain text only
= JSON is language-neutral and easy to read; formats like Protobuf are used for gRPC.

Q E Which HTTP method fetches data without changing it?
+ GET
- POST
- PATCH
- DELETE
= GET is safe (no side effects) and idempotent, so it can be cached and retried.

Q E What does an API gateway do?
+ One entry point that routes requests and handles auth and rate limits
- A shared database that every service reads and writes directly
- A build server that compiles and deploys all the services
- A replacement for the database layer that caches every query
= Clients call the gateway instead of each service directly.

Q M What does a circuit breaker do?
+ Stops calling a failing service for a while to avoid cascading failures
- Encrypts all traffic between services so failures cannot leak data
- Splits a database into shards when one shard starts failing
- Balances CPU between containers when one service is overloaded
= After repeated failures it "opens" and fails fast, then lets a few test calls through before closing.

Q M Why should each microservice own its own database?
+ So a service can change its schema without breaking others
- Because separate databases cost less than one shared database
- Because SQL joins across services run faster that way
- Because the HTTP standard requires one database per service
= A shared database couples services tightly; others get data through the owning service's API or events.

Q M What is an idempotency key in a payments API for?
+ Letting a client retry safely without being charged twice
- Encrypting card numbers before they reach the server
- Making payment responses come back faster
- Identifying which user made the payment request
= The server stores the result per key and returns it again for a repeated request.

Q M What is a JWT?
+ A signed token with claims a server can verify without a session store
- An encrypted database file that stores each user's session
- A Java web toolkit for building login pages and forms
- A special cookie that only administrators are allowed to use
= The signature proves the token was not changed; its contents are readable unless also encrypted.

Q H Which pattern handles a business transaction that spans several services?
+ Saga: local transactions with compensating steps on failure
- Two-phase commit across every service on each request
- One global lock that every service takes before writing
- Retrying the whole request until every service succeeds
= e.g. if payment fails after stock is reserved, a compensating step releases the stock.

Q H Why add random jitter to exponential backoff when retrying?
+ To spread retries so many clients don't retry at the same moment
- To make each retried request smaller than the original
- To encrypt retried requests so they cannot be replayed
- To guarantee that each request is retried exactly once
= Without jitter, clients that failed together retry together and overload the service again.

Q H How does the cache-aside pattern work?
+ Read the cache; on a miss load from the DB and cache it; on writes update the DB and evict
- The database pushes every change straight into all caches as it happens
- Entries are written once and never invalidated, so reads are always fast
- Writes go only to the cache, which copies them to the database later
= It is simple and common; stale reads are limited by eviction on write and by expiry times.

Q H What are the three pillars of observability?
+ Logs, metrics and traces
- CPU, memory and disk
- Unit, integration and end-to-end tests
- Development, testing and production
= Distributed tracing (e.g. OpenTelemetry) follows one request across many services.

Q E What is a monolith?
+ One deployable app containing all features
- A database shared by many services
- A service with only one endpoint
- A server running a single thread
= Monoliths are simpler to start with; split when needed.

Q E Which HTTP status means the request succeeded?
+ 200
- 301
- 404
- 503
= 201 for created, 204 for success with no body.

Q E What does service discovery solve?

- Finding bugs in services before they ship
- Discovering which users call each service
- Listing the classes inside each service
= Kubernetes DNS or Eureka are common options.

Q E What does a load balancer do?
+ Spreads requests across several instances
- Stores data across several databases
- Compresses responses to save bandwidth
- Checks the code of each service
= Health checks take failed instances out of rotation.

Q E Which HTTP method should create a new resource?
+ POST
- GET
- HEAD
- OPTIONS
= PUT replaces a resource at a known URL.

Q E What does a message queue such as RabbitMQ or Kafka allow?

- Services to share one database
- Services to run on one thread
- Services to skip authentication
= The sender doesn't wait for the receiver.

Q E What is an API?
+ A defined way for programs to talk
- A database table shared between teams
- A user interface for administrators
- A file format used for storing logs
= REST, gRPC and GraphQL are common API styles.

Q E What does HTTP status 500 mean?
+ The server hit an unexpected error
- The client sent a bad request
- The resource was not found
- The user is not logged in
= 4xx means the client's fault; 5xx the server's.

Q E What is a container image used for in microservices?
+ Packaging a service with all it needs
- Storing the pictures uploaded by users
- Backing up the service's own database
- Drawing the system's architecture diagram
= Docker images run the same in every environment.

Q E What is a health check endpoint?
+ A URL reporting if the service works
- A page listing the service's users
- A test run before each deployment
- A log of the service's past outages
= Spring Boot Actuator offers /actuator/health.

Q E What is rate limiting?
+ Capping how many requests a client can make

- Limiting the size of the database
- Counting lines of code per service

Q E Why version an API, e.g. /v1/orders?

Q E What does a distributed trace show?

Q M What is eventual consistency?

Q M What is the purpose of a timeout on an outbound HTTP call?

Q M What does the bulkhead pattern do?

- Stores responses until the service recovers

Q M What is gRPC?

Q M What is the outbox pattern for?

- The resource has moved permanently elsewhere

- It guarantees the email arrives instantly

Q H Why can retries make an outage worse?

- Retries make each request use less CPU on the server
- Retries can only happen once per minute in HTTP

Q H Two services need to show data joined from both. What avoids a distributed join at request time?

- Calling both services in a loop for every row
- Merging the two services into one database schema

Q H What makes a contract test (e.g. Pact) useful between services?

- It replaces every unit test with a single shared test suite for all teams
- It verifies the legal contract between the companies that own the services
= Breaking changes are caught in the provider's build.

Q H What is the main trade-off of moving from a monolith to microservices?

- Faster local builds, but no ability to scale services independently anymore
- Better consistency, at the cost of fewer API endpoints in the system

Q H What does a 429 response with Retry-After ask a well-behaved client to do?

- Switch to a different API version
- Re-authenticate before calling again
= Respecting it keeps clients from being blocked.

Q H Why is distributed caching with a short TTL often paired with cache stampede protection?

- Short TTLs make the cache use more disk space
- Caches can't hold data for less than a minute
- Stampedes only happen with long TTLs

- Make the client wait 10 seconds between calls
- Use GET instead of POST for payments

Q H What does "smart endpoints, dumb pipes" mean?

- Every endpoint must use AI to route its requests
- Pipes must be encrypted while endpoints stay plain

Q H A team splits a monolith into 30 services, all deployed together every Friday. What have they built?

- A serverless system that scales each function alone
- A modular monolith with clean internal boundaries
= If services can't be deployed independently, the split adds network cost without autonomy.
