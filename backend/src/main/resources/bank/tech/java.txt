@topic java-exceptions | FUNDAMENTALS | Exceptions | try/catch/finally, checked vs unchecked, throw vs throws, try-with-resources, custom exceptions, good practice.
Q E Which block runs whether or not an exception is thrown (unless the JVM exits)?
+ finally
- catch
- throw
- final
= finally runs after try (and any catch), even when try returns or throws.

Q E Which of these is a checked exception?
+ IOException
- NullPointerException
- ArithmeticException
- ArrayIndexOutOfBoundsException
= Checked exceptions extend Exception but not RuntimeException; the compiler makes you catch or declare them.

Q E What does throws in a method signature mean?
+ The method may pass this exception to its caller
- The method catches this exception inside itself
- The method throws this exception on every call
- The exception is logged and then ignored
= throws declares exceptions that can leave the method; throw actually raises one.

Q E What happens when this line runs?
| int x = 10 / 0;
+ An ArithmeticException is thrown
- x becomes 0 and a warning is logged
- x becomes Infinity, like double division
- x becomes NaN because the result is undefined
= Integer division by zero throws ArithmeticException. (Floating-point 10.0 / 0 gives Infinity.)

Q M What does this print?
| static int f() {
|     try { return 1; }
|     finally { System.out.print("F "); }
| }
|
| System.out.println(f());
+ F 1
- 1
- 1 F
- Compile error
= The return value is computed, finally runs (printing "F "), then the value 1 is returned and printed.

Q M What is try-with-resources for?
+ Closing files and connections automatically
- Retrying a block automatically when it fails
- Catching every exception the block may throw
- Running each resource's code in parallel
= Resources declared in try (...) that implement AutoCloseable are closed at the end, even on error.

Q M What happens with these catch blocks?
| try {
|     Files.readString(Path.of("a.txt"));
| } catch (Exception e) {
|     System.out.println("any");
| } catch (IOException e) {
|     System.out.println("io");
| }
+ Compile error: the IOException catch is unreachable
- It prints "io" when the file is missing
- It prints "any" and then "io" for a missing file
- It compiles and always prints "any" on failure
= Catch the most specific type first. A subclass catch after its superclass is unreachable code.

Q M Which is good practice with exceptions?
+ Catch only what you can handle; log or rethrow the rest
- Catch Throwable everywhere so nothing escapes
- Use empty catch blocks to keep logs clean
- Use exceptions to end normal loops
= Swallowing exceptions hides bugs; exceptions are for exceptional cases, not flow control.

Q H What does this print?

|     int x = 1;
|     try { return x; }
|     finally { x = 2; }
| }
|
| System.out.println(g());
+ 1
- 2
- 0
- Compile error
= The value of x (1) is saved when return runs; changing x in finally does not change it.

Q H What does this print?
| static int h() {
|     try { throw new RuntimeException("boom"); }
|     finally { return 3; }
| }
|
| System.out.println(h());
+ 3
- A RuntimeException stack trace
- Compile error
- 0
= A return in finally discards the pending exception, which is why returning from finally is a bad idea.

Q H When should a custom exception extend RuntimeException rather than Exception?
+ When callers are not expected to recover, e.g. bad input
- When every caller must be forced by the compiler to handle it
- Never; custom exceptions in Java must always be checked
- Only when the exception is thrown from the main method
= Unchecked exceptions suit errors callers cannot sensibly handle; checked ones force handling of recoverable cases.

Q H In try-with-resources, the body throws and then close() also throws. What reaches the caller?
+ The body's exception, with close()'s attached as suppressed
- The close() exception, which replaces the body's exception
- Neither; both exceptions are swallowed by the try block
- Both, thrown one after another to the calling method
= Java keeps the original exception and records the other via getSuppressed().

Q M What is the N+1 query problem?

- Each request opens N+1 database transactions instead of one
- An index has N+1 columns, which makes every write slower
= For 100 orders that is 101 queries. Fetch joins or entity graphs load the data in one go.

Q M What is the default fetch type of @OneToMany in JPA?
+ LAZY
- EAGER
- IMMEDIATE
- NONE
= Collections are lazy by default; @ManyToOne and @OneToOne are eager by default.

Q M What does LazyInitializationException usually mean?
+ A lazy relation was read after the session (transaction) closed
- The database server went down while an entity was being loaded
- Two threads updated the same row at the same time
- The entity class is missing an @Id field
= Load what you need inside the transaction, e.g. with a fetch join or a DTO query.

Q M What does this Spring Data JPA method do?
| List<User> findByEmail(String email);
+ Spring builds the query from the method name
- Nothing happens until you add an @Query with SQL
- It always finds users by their primary key
- It fails to compile without an implementation
= Derived queries parse names like findByEmailAndActive into JPQL.

Q H What does optimistic locking with @Version do?
+ An update fails if someone else changed the row since it was read
- Every row is locked as soon as it is read, until the commit
- Only one user at a time can open the record for editing
- The database records each version of the table's schema
= Each update checks and bumps the version column; a stale version raises OptimisticLockException.

Q H How do you avoid N+1 queries when loading orders with their items?
+ Use JOIN FETCH or an entity graph to load both in one query
- Make every relation EAGER so JPA always loads items too
- Add more database connections so the extra queries run in parallel
- Call findAll() twice so the second call hits the cache
= EAGER everywhere loads too much and can still cause N+1; fetch exactly what each use case needs.

Q H A @Transactional method throws a checked exception. By default, what happens to the transaction?
+ It commits; by default only unchecked exceptions roll back
- It rolls back, as it does for every exception type
- It stays open until the caller commits it manually
- It is retried once and then rolled back if it fails again
= Use @Transactional(rollbackFor = Exception.class) if checked exceptions should roll back too.

Q H Why mark a query method @Transactional(readOnly = true)?
+ Hibernate can skip dirty checking and flushing
- It stops the method from running SELECT queries
- It makes INSERT and UPDATE statements run faster
- It turns off the first-level cache for the method
= Read-only transactions avoid tracking changes to loaded entities; some setups also route them to read replicas.

@topic java-concurrency | ADVANCED | Concurrency | Threads and Runnable, synchronized and volatile, race conditions, executors, CompletableFuture, concurrent collections, deadlocks, virtual threads.
Q E Which is a way to run a task in a separate thread?
+ Pass a Runnable to a new Thread, then call start()
- Override toString() and call it from main
- Declare the method static and call it directly
- Call the method inside a for loop with a sleep
= You can also submit tasks to an ExecutorService, which is usually better.

Q E What does synchronized guarantee?
+ Only one thread at a time runs code guarded by the same lock
- The method is compiled ahead of time so it runs faster
- The method's work is split across every CPU core
- The method's local variables can never be changed
= It also makes changes made inside the block visible to the next thread that takes the lock.

Q E What happens if you call run() instead of start() on a Thread?
+ run() runs in the current thread; no new thread starts
- Two threads start: one for run() and one for start()
- An IllegalThreadStateException is thrown at once
- Nothing happens until start() is also called
= start() creates the new thread, which then calls run().

Q E What is a deadlock?
+ Threads waiting forever for locks held by each other
- A thread that finishes before the others have started
- A JVM crash caused by running too many threads
- A thread stuck in an infinite loop of its own
= e.g. thread 1 holds A and waits for B while thread 2 holds B and waits for A.

Q M What does volatile guarantee?
+ Writes are visible to other threads, but count++ is still not atomic
- Every operation on the variable, including count++, becomes atomic
- The whole object is locked while the variable is being changed
- The variable can never be null once it has been assigned
= count++ is read-modify-write; use AtomicInteger or a lock for that.

Q M What does this print?
| int[] count = {0};
| Runnable r = () -> { for (int i = 0; i < 100_000; i++) count[0]++; };
| Thread a = new Thread(r), b = new Thread(r);
| a.start(); b.start();
| a.join(); b.join();
| System.out.println(count[0]);
+ Up to 200000, often less, because ++ is not atomic
- Always 200000, because join() waits for both threads
- Always 100000, because the threads share one loop
- It fails to compile: arrays cannot be used in lambdas
= Both threads can read the same old value and write back the same result, losing updates (a race condition).

Q M Why use an ExecutorService rather than creating threads by hand?
+ It reuses pooled threads and manages queuing and shutdown
- It removes the need for any synchronization in tasks
- It runs every task on the main thread, one at a time
- Java no longer allows creating threads by hand
= Creating a thread per task is expensive and unbounded; pools cap and reuse them.

Q M Which map is safe for concurrent puts and gets from many threads?
+ ConcurrentHashMap
- HashMap
- TreeMap
- LinkedHashMap
= ConcurrentHashMap allows concurrent access without locking the whole map; HashMap can corrupt under concurrent writes.

Q H What does this return?
| CompletableFuture.supplyAsync(() -> 2)
|     .thenApply(x -> x * 3)
|     .thenCombine(CompletableFuture.supplyAsync(() -> 4), Integer::sum)
|     .join();
+ 10
- 24
- 14
- 9
= 2 × 3 = 6, then combined with 4 by addition: 10.

Q H What is a reliable way to prevent deadlocks between locks?
+ Always acquire locks in the same global order
- Start more threads so one of them always gets the lock
- Make every method static so there is only one lock
- Catch InterruptedException around each lock call
= If every thread takes A before B, a cycle of waiting cannot form. tryLock with a timeout also helps.

Q H How does AtomicInteger.incrementAndGet() work internally?
+ A lock-free compare-and-swap (CAS) loop
- A synchronized block around the increment
- A dedicated thread that performs the increment
- A volatile write followed by a full memory flush
= CAS retries until no other thread changed the value in between, avoiding locks.

Q H Virtual threads (Java 21) are best suited for:
+ Many concurrent tasks that mostly wait on I/O
- CPU-heavy number crunching on every core
- Replacing every synchronized block in the code
- Rendering a desktop GUI on the main thread
= They are cheap to create and park while blocked; they do not make CPU-bound work faster.

@topic java-jvm | ADVANCED | JVM, memory and performance | Heap and stack, garbage collection and pauses, memory leaks, OutOfMemoryError, JIT, JVM flags, heap dumps, class loading.
Q E Where are objects created with new stored?
+ On the heap
- On the stack
- In the method's bytecode
- Only in the CPU cache
= Local primitives and references live on each thread's stack; the objects themselves live on the heap.

Q E What does the garbage collector do?
+ Frees memory of objects that are no longer reachable
- Deletes source files that are no longer referenced
- Closes database connections that have been idle
- Compiles Java source code to bytecode at run time
= Objects with no live references can be collected; you never free memory by hand.

Q E What runs compiled Java bytecode (.class files)?
+ The JVM
- javac
- The operating system directly
- Maven
= javac compiles source to bytecode; the Java Virtual Machine runs it on any platform.

Q E What usually causes a StackOverflowError?
+ Method calls nested too deeply, usually endless recursion
- Too many objects created on the heap at the same time
- Writing to a disk that has no free space left
- Dividing an integer by zero inside a loop
= Each call adds a frame to the thread's stack; recursion without a base case fills it.

Q M "OutOfMemoryError: Java heap space" usually means:
+ The heap is full of reachable objects: too small, or a leak
- The call stack is too deep because of endless recursion
- The CPU is overloaded and the JVM cannot keep up
- The disk is full, so the JVM cannot swap memory out
= Check a heap dump to see what is holding memory before simply raising -Xmx.

Q M Can a Java program leak memory even with garbage collection?
+ Yes, if objects stay reachable by mistake, e.g. a growing static map
- No, because the garbage collector frees every unused object
- Only in native code called through JNI, never in plain Java
- Only when arrays are used, because they are never collected
= GC frees unreachable objects only; forgotten references (caches, listeners, ThreadLocals) keep objects alive.

Q M What is JIT compilation?
+ The JVM compiles hot bytecode to native code while the program runs
- javac compiles Java source to native code before the program runs
- The JVM interprets every bytecode instruction for the program's life
- A tool compiles Java to JavaScript so it can run in a browser
= Hot methods get optimised machine code, which is why Java speeds up after warm-up.

Q M What is the difference between the JDK and the JRE?
+ The JDK includes build tools like javac; the JRE only runs programs
- They are the same download under two different names
- The JRE is the newer replacement for the JDK
- The JDK is used only for building Android apps
= Since Java 11 you usually install a JDK and can build slim runtimes with jlink.

Q H Which JVM option sets the maximum heap size?
+ -Xmx
- -Xss
- -Xms
- -XX:MaxStack
= -Xmx is the maximum heap, -Xms the initial heap and -Xss the per-thread stack size.

Q H What does a heap dump help you find?
+ Which objects use memory and what keeps them alive
- Which SQL queries are slow and how often they run
- Where network latency comes from between services
- Which lines of code have compiler warnings
= Tools like Eclipse MAT show retained sizes and the reference paths to GC roots.

Q H Why do garbage-collection "stop-the-world" pauses matter for web services?
+ All app threads pause, which shows up as latency spikes
- They free memory faster, so requests get quicker
- They only happen once, while the app is starting up
- They pause the database while memory is reclaimed
= Collectors such as G1 and ZGC aim to keep these pauses short.

Q H How does the default class-loader delegation work?
+ A loader asks its parent first and loads the class itself only if the parent can't
- A loader always loads the class itself first and asks its parent only on failure
- All classes are loaded together at compile time, so there is no delegation
- Classes are loaded in alphabetical order by the system class loader
= Parent-first delegation stops application code from replacing core classes such as java.lang.String.

@topic java-design | ADVANCED | Design principles and patterns | SOLID, singleton, factory, builder, strategy, observer and decorator patterns, immutability, refactoring code smells.
Q E What does the Single Responsibility Principle say?
+ A class should have one reason to change
- A class should be a singleton
- Every class should have one method
- Only one developer should edit a class
= Keeping one job per class makes changes smaller and safer.

Q E Which pattern makes sure a class has only one instance?
+ Singleton
- Factory
- Observer
- Adapter
= In Spring, beans are singletons by default, so you rarely hand-write this pattern.

Q E When is the Builder pattern useful?
+ Creating objects with many optional fields readably
- Making a class safe to share between threads
- Iterating over the elements of a collection
- Writing log messages in a consistent format
= e.g. User.builder().name("Asha").email("a@x.com").build() instead of a long constructor.

Q E What does DRY stand for?
+ Don't Repeat Yourself
- Do Run Yearly
- Data Requires Yielding
- Design, Review, Yield
= Keep each piece of knowledge in one place so a change is made once.

Q M What does the Open/Closed Principle mean?
+ Open for extension, closed for modification
- Classes should be open source and freely shared
- Fields should be public so others can extend them
- Files should be closed as soon as they are read
= Add new behaviour with new classes (e.g. a new strategy) rather than editing working code.

Q M What does the Strategy pattern do?
+ Swaps algorithms at run time behind a common interface
- Notifies many objects automatically when one object changes
- Wraps an object to add behaviour without changing its class
- Creates families of related objects without naming classes
= e.g. different PaymentStrategy implementations chosen per order.

Q M Why prefer immutable objects?
+ They are thread-safe and easier to reason about
- They always use less memory than mutable objects
- They are faster to create than mutable objects
- They are never removed by the garbage collector
= An object that cannot change can be shared freely between threads without locks.

Q M What does the Dependency Inversion Principle say?
+ High-level code should depend on abstractions, not concrete classes
- Lower layers should call upper layers instead of the other way round
- Every if condition should be inverted to reduce nesting in methods
- Dependencies should be listed in reverse order in the build file
= Depending on an interface (e.g. PaymentGateway) lets you swap implementations and test easily.

Q H Which is a classic violation of the Liskov Substitution Principle?
+ Square extends Rectangle, and setting the width also sets the height
- A class implements two interfaces that declare the same method
- An abstract class declares a constructor that subclasses must call
- A final class cannot be extended by any other class
= Code written for Rectangle breaks when given a Square, so Square is not a safe substitute.

Q H Which is a correct thread-safe, lazy singleton in Java?
+ The initialization-on-demand holder class, or an enum with one value
- A static field set in a getter without any synchronization
- Creating a new instance on every call
- Cloning the instance
= The JVM initialises the holder class only on first use, safely across threads.

Q H Where do you see the Observer pattern in practice?
+ Event listeners and publish–subscribe, e.g. Spring events
- Builders that create objects with many optional fields
- Database indexes that speed up lookups by key
- Logging levels that filter messages by importance
= Subjects publish events; observers react without the subject knowing them directly.

Q H What is the best fix for a "God class" that does everything?
+ Split it into smaller classes with one responsibility each
- Make all its methods static so it needs no instance
- Add detailed comments explaining every method in it
- Rename it so its name matches what it mostly does
= Extract cohesive groups of fields and methods into their own classes.

@topic java-microservices | ADVANCED | Microservices and system design | Service boundaries, API gateways, REST vs messaging, resilience (circuit breakers, retries), idempotency, sagas, caching, JWT security, observability.
Q E What is a microservice?
+ An independently deployable service owning one business capability
- Any class in the codebase that has fewer than 100 lines of code
- A function inside a monolith that is called over HTTP internally
- A database table that is accessed by only one application
= Each service can be built, deployed and scaled on its own.

Q E Which format do most REST APIs use for request and response bodies?
+ JSON
- CSV
- Binary serialized Java objects
- Plain text only
= JSON is language-neutral and easy to read; formats like Protobuf are used for gRPC.

Q E Which HTTP method fetches data without changing it?
+ GET
- POST
- PATCH
- DELETE
= GET is safe (no side effects) and idempotent, so it can be cached and retried.

Q E What does an API gateway do?
+ One entry point that routes requests and handles auth and rate limits
- A shared database that every service reads and writes directly
- A build server that compiles and deploys all the services
- A replacement for the database layer that caches every query
= Clients call the gateway instead of each service directly.

Q M What does a circuit breaker do?
+ Stops calling a failing service for a while to avoid cascading failures
- Encrypts all traffic between services so failures cannot leak data
- Splits a database into shards when one shard starts failing
- Balances CPU between containers when one service is overloaded
= After repeated failures it "opens" and fails fast, then lets a few test calls through before closing.

Q M Why should each microservice own its own database?
+ So a service can change its schema without breaking others
- Because separate databases cost less than one shared database
- Because SQL joins across services run faster that way
- Because the HTTP standard requires one database per service
= A shared database couples services tightly; others get data through the owning service's API or events.

Q M What is an idempotency key in a payments API for?
+ Letting a client retry safely without being charged twice
- Encrypting card numbers before they reach the server
- Making payment responses come back faster
- Identifying which user made the payment request
= The server stores the result per key and returns it again for a repeated request.

Q M What is a JWT?
+ A signed token with claims a server can verify without a session store
- An encrypted database file that stores each user's session
- A Java web toolkit for building login pages and forms
- A special cookie that only administrators are allowed to use
= The signature proves the token was not changed; its contents are readable unless also encrypted.

Q H Which pattern handles a business transaction that spans several services?
+ Saga: local transactions with compensating steps on failure
- Two-phase commit across every service on each request
- One global lock that every service takes before writing
- Retrying the whole request until every service succeeds
= e.g. if payment fails after stock is reserved, a compensating step releases the stock.

Q H Why add random jitter to exponential backoff when retrying?
+ To spread retries so many clients don't retry at the same moment
- To make each retried request smaller than the original
- To encrypt retried requests so they cannot be replayed
- To guarantee that each request is retried exactly once
= Without jitter, clients that failed together retry together and overload the service again.

Q H How does the cache-aside pattern work?
+ Read the cache; on a miss load from the DB and cache it; on writes update the DB and evict
- The database pushes every change straight into all caches as it happens
- Entries are written once and never invalidated, so reads are always fast
- Writes go only to the cache, which copies them to the database later
= It is simple and common; stale reads are limited by eviction on write and by expiry times.

Q H What are the three pillars of observability?
+ Logs, metrics and traces
- CPU, memory and disk
- Unit, integration and end-to-end tests
- Development, testing and production
= Distributed tracing (e.g. OpenTelemetry) follows one request across many services.
